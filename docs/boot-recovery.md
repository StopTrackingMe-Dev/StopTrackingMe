# 重启与无障碍恢复

用户首次在系统设置开启无障碍后，Android 保存启用状态并负责重新绑定服务。应用不会通过开机广播启动无障碍 Service、修改安全设置或开启 Activity。服务组件名保持不变，便于系统在应用升级后继续识别授权。

服务支持 Direct Boot。首次解锁前只注册恢复监听，不读取规则、偏好、剪贴板或分享数据；无需将这些数据迁入设备保护存储。收到动态 USER_UNLOCKED 广播后初始化业务，BOOT_COMPLETED 和 MY_PACKAGE_REPLACED 提供幂等恢复信号。服务晚于广播绑定也会自行检查解锁状态并初始化，不依赖首页启动。

首页分别检查系统中的准确服务组件和当前进程的连接状态，不再将上次保存的“已连接”消息当作实际连接。自启动和省电引导保留在设置页。

普通应用不能重新授予已关闭的无障碍权限。厂商限制、用户强行停止或手动关闭权限仍可能阻止恢复，需要用户在系统设置处理。

## 真机验收

1. 安装并开启一次无障碍，允许厂商自启动、后台活动并取消电池限制。用受支持应用确认分享净化正常。
2. 设置锁屏 PIN 后正常重启，不启动本应用。首次解锁前检查日志无加密存储访问崩溃；解锁后直接在受支持应用分享，确认监听恢复。
3. 再次锁屏、解锁，确认不会重复创建悬浮窗或恢复旧的分享任务。
4. 覆盖安装同签名更新，确认授权保留且分享恢复。重复开机/恢复信号应无额外界面或后台服务。
5. 主动关闭无障碍，确认应用不会重新打开开关，首页显示未授权。强行停止后重新打开应用，确认断连提示符合实际状态。
6. 至少在原生 Android 和目标厂商 ROM 分别测试；后台限制开启时不应承诺自动恢复成功。

参考：[Android 无障碍服务生命周期](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[Direct Boot 与首次解锁](https://developer.android.com/privacy-and-security/direct-boot)。
